# Публикация на GitHub — пошагово

## 0. Перед первой публикацией (обязательно)

- [ ] **LICENSE:** впишите владельца вместо `[ВЛАДЕЛЕЦ — …]` и убедитесь, что MIT подходит компании
      (альтернативы: Apache-2.0 — с явной патентной оговоркой; GPL-3.0 — если производные тоже должны быть открытыми).
- [ ] **Нет данных компании:** IFC, `labels*.xlsx`, `corrections*.csv`, `company_settings.json`,
      адреса серверов, имена сотрудников. `.gitignore` их отсекает, но проверьте `git status` перед первым коммитом.
- [ ] **Таблица правил** `rules/Правила_АГР.xlsx` — это экспертиза компании. Публикуем её как пример/шаблон?
      Если нет — замените на урезанную версию.
- [ ] **Классификаторы МССК** (`rules/classifiers/*.txt` и листы «Кл. …» в таблице правил) — тексты
      публичных классификаторов exp.mos.ru. Убедитесь, что их можно распространять; если нет — удалите
      их из репозитория и оставьте инструкцию `tools/mssk_pdf_to_txt.py`.
- [ ] **Иконка** `plugin/RevitAIClassifier/Resources/` — своя или с правом использования.

## 1. Создать репозиторий

1. github.com → **New repository** → имя `atributy-agr`, **Public**, без README/LICENSE (они уже есть).
2. Локально, в папке репозитория:

```bash
git init
git add .
git status            # ещё раз посмотрите, что попадает в коммит
git commit -m "АтрибутыАГР 1.4: первая публикация"
git branch -M main
git remote add origin https://github.com/<владелец>/atributy-agr.git
git push -u origin main
```

Вкладка **Actions** → workflow **CI** должен пройти: тесты сервиса, сборка плагина, сборка Docker-образа.

## 2. Выпустить версию (Release)

```bash
git tag v1.4.0
git push origin v1.4.0
```

Workflow **Release** соберёт и приложит к релизу:
- `AtributyAGR_Revit2020-2026_Setup_1.4.0.exe` — установщик плагина для всех версий Revit (адрес сервера по умолчанию `http://SERVER:8765`,
  пользователь вписывает свой при установке);
- `AtributyAGR_Trainer_1.4.0.zip` — программа обучения с таблицей правил и классификаторами;
- Docker-образ `ghcr.io/<владелец>/atributy-agr-service:v1.4.0` и `:latest`
  (Settings → Packages → сделайте пакет Public, если нужно скачивать без входа).

Через 15–20 минут после `git push` тега готовые файлы появятся на странице **Releases** —
давайте коллегам ссылку на неё. Если образ должен скачиваться без входа в GitHub:
**Packages → atributy-agr-service → Package settings → Change visibility → Public**.

Установщик **для своей компании** (с вашим адресом сервера и маппингом) собирайте локально —
см. [plugin.md](plugin.md): он содержит внутренние данные и в публичный релиз не идёт.

## 3. Настройки репозитория (рекомендуется)

- **Settings → Branches → Add rule** для `main`: требовать прохождения CI перед слиянием.
- **About** (справа на главной): описание, тема `revit`, `bim`, `ifc`, `machine-learning`, `fastapi`.
- **Issues** — включены; при желании шаблоны в `.github/ISSUE_TEMPLATE`.
- **Security → Private vulnerability reporting** — включить.

## 4. Как работать дальше

| Действие | Как |
|---|---|
| правка кода | ветка → Pull Request → CI зелёный → слияние в `main` |
| новая версия | обновить `CHANGELOG.md` → тег `vX.Y.Z` → релиз соберётся сам |
| данные компании | только на сервере (`deploy/data`) и у BIM-менеджера, не в git |

## Если CI упал

- **Плагин, пакеты `Nice3point.Revit.Api.*`** — откройте лог шага сборки: если пакет не найден,
  проверьте версию на nuget.org и поправьте `Version="2022.*"` в `.csproj`.
- **Тесты** — `pip install -r requirements-dev.txt && pytest -q` локально покажет то же.
- **Inno Setup на релизе** — проверьте путь `ISCC.exe` в `release.yml`.
