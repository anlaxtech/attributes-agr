# Таблица правил (`rules/Правила_АГР.xlsx`)

Источник правды для правил. Копия компании лежит на сервере как `deploy/data/rules.xlsx`.
Подсказки — в примечаниях к заголовкам и на листе «Как заполнять».

## Листы

| Лист | Что |
|---|---|
| Правила | одна строка — одно правило |
| Параметры | порядок заполнения, источник значения, классификатор, колонка выгрузки IFC |
| Типы файлов | часть имени файла Revit → план / паркинг / фасад (`*` — по умолчанию) |
| Кл. Элементы / Материалы / Помещения | классификаторы МССК |

## Правило

Если **все** заполненные условия выполнены — параметр получает значение. Пусто — «неважно».
Варианты через запятую, `!` — «НЕ», `гкл+перегородк` — обе части сразу.

| Колонка | Пример |
|---|---|
| Параметр | `RUS_MSSK_Element_Code` |
| IFC-класс | `IfcWall` (результат IfcExportAs; пусто — все) |
| Значение | код или наименование (`Стекло`); `{thick}` — ссылка на признак; `исключить` |
| Как применять | *правило* / *правило, сверить с моделью* / *только обучение* |
| Приоритет | меньше — раньше |
| Условия | категория, тип файла, тип фасада, имя содержит / не содержит, материал, толщина от/до, стена-витраж, внутри витража, створка с дверью, из помещения / в помещение, условие по параметру |

«Условие по параметру»: `space_name=ЛК`, `zone_has_apartments=да`,
`RUS_MSSK_Element_Code=ЭЛ 30 18 30 31` (уже найденное значение).

Параметр **«Исключить элемент»** = `да` убирает элемент из проверки и записи целиком
(например, проёмы и лифты).

## Проверка правил на выданных IFC

```bash
python python/check_rules.py rules/Правила_АГР.xlsx <папка_с_ifc>
```

→ `rules_report.xlsx`: покрытие, совпадения с IFC по каждому правилу, расхождения, что уйдёт на обучение.
